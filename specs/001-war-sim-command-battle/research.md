# Research: 战争幻想模拟器 —— 确定性并行、AI 接入与 v1 规模（Phase 0 输出）

> 本文件为 `/speckit-plan` Phase 0 输出，将 Technical Context 中的未知项收敛为"决策 + 理由 + 备选"。所有数值为设计基线，具体校准在实现阶段以数据驱动配置完成。

## 1. 多线程更新与确定性兼容（FR-025 / SC-001）

- **Decision**: 采用**确定性分区并行**：每个固定 tick 内，把实体按空间区域/实体分桶到固定数量的工作桶；跨分区交互（如跨区射击、支援请求）不在桶内直接结算，而是在**固定边界同步点**统一收集、按确定性顺序处理；每桶结果按**固定归约顺序**合并。线程池大小可配置（`--threads`），只影响性能，不影响状态哈希。
- **Rationale**: 线程调度天然不确定，若让不同线程以任意顺序消费共享事件，相同输入会产出不同结果。分区 + 边界同步把并行度隔离在"互不影响的子问题"内，跨区交互收敛到确定性序列，从而保证 1 线程与 N 线程状态哈希一致。
- **Alternatives considered**:
  - 单线程更新：最简单、最稳，但用户决定 v1 即采用多线程；
  - 实体级工作窃取：负载均衡好，但窃取顺序破坏确定性，被否决；
  - 全量双缓冲两阶段提交：确定性可保证，但内存与复杂度高，v1 不采用。
- **实施要点**: `sim/src/parallel.cpp` 实现分桶与归约；黄金测试必须包含"同种子 1 线程 vs N 线程状态哈希一致"门禁（`sim_tests`）。

## 2. 统一随机源（宪法第 7 条）

- **Decision**: PCG32，显式种子；每个分桶分配**固定子流**（种子 + 桶序号派生），桶内随机消费顺序固定；RNG 仅由模拟核心消费，AI/UI 线程不得接触。
- **Rationale**: PCG32 状态小、分片容易，按桶固定子流后并行分桶各自独立推进，归约时不需要合并随机状态。
- **Alternatives considered**: MT19937（状态大、分片困难）、xoshiro256（性能相近，但 PCG32 生态成熟、已有头文件实现）。

## 3. 时间模型与 tick（宪法第 16 条 / FR-025）

- **Decision**: 固定 tick 20 Hz；游戏时钟为离散 tick 计数（游戏时间戳 = tick × 50 ms）；禁止现实时钟参与结算；暂停/加速只改变"现实时间 → 游戏时间"的映射，发生在表现层。
- **Rationale**: 20 Hz 足以支撑战术级单位机动与火力交互，且每 tick 计算量可控（营级 300–800 实体）。
- **Alternatives considered**: 可变步长（破坏确定性）、60 Hz（v1 营级规模无必要，留待后续）。

## 4. 线程模型（FR-025）

- **Decision**: 模拟工作线程池（默认 4，可配 1–8）只处理分桶；AI 调用、UI 渲染、存档 IO 各自独立线程，与模拟 tick 解耦。
- **Rationale**: AI 延迟、渲染帧率、存档写入都不应阻塞模拟；分离后模拟 tick 的墙钟预算（≤5 ms）稳定。
- **Alternatives considered**: 模拟线程与 AI 线程共池（调度耦合，风险高）；完全单线程（被否决）。

## 5. C ABI 互操作边界（宪法第 14 条）

- **Decision**: `sim` 暴露纯 C ABI（`wfs_sim_*`）：不透明句柄 + `wfs_sim_result` 错误码；快照以只读 JSON 结构输出；命令/事件以纯数据注入；ABI 版本号 `wfs_sim_version` 防错配。
- **Rationale**: C# 通过 P/Invoke 调用 C ABI 最稳，避免 C++/CLI 与跨语言对象生命周期问题；纯数据边界符合宪法"跨层只传纯数据"。
- **Alternatives considered**: C++/CLI（生命周期复杂、维护差）；gRPC/进程隔离（v1 单机无必要）。

## 6. AI 接入（FR-068/069、宪法第 8/9/11 条）

- **Decision**: v1 双后端——云端模型（OpenAI 兼容 REST）与无 AI 脚本模式（确定性脚本 AI）；本地模型后置（后端抽象预留）。AI 输出必须通过 JSON Schema + 语义校验；非法/超时拒绝或降级到脚本；决策经 `wfs_sim_inject_ai_decision` 注入确定性命令队列（tick + 单调序列号排序）；决策日志 JSONL 记录状态快照、输入、输出。
- **Rationale**: 云端是核心玩法来源，脚本模式保证离线与可靠性（Assumptions：云端是 v1 唯一网络依赖）；注入队列 + 校验让 AI 成为"外部输入"而非随机源，确定性链条完整。
- **Alternatives considered**: 本地模型进 v1（增加集成与硬件面，后置）；直接让 AI 写模拟状态（违反宪法第 9 条，否决）。

## 7. 数据驱动与存档（宪法第 12/13 条）

- **Decision**: 一切可自定义内容以 JSON 数据定义（派系模板、剧本、单位/武器/弹药/地形/工事），加载时 JSON Schema + 语义校验，非法数据报错不崩溃；存档格式 `WFS-SAVE` + `format_version` + `header_json` + `state_blob` + 迁移链。
- **Rationale**: 派系差异、剧本、数值模型全部以数据承载，新增内容不改代码；存档版本化保证破坏性变更可迁移（宪法第 13 条）。
- **Alternatives considered**: 二进制协议直写（难迁移、难校验）；数据库（单机游戏无必要）。

## 8. v1 规模与性能预算（FR-001 / Assumptions）

- **Decision**: v1 场景 = 营级对抗（双方各一个营级单位群，5×5 km）+ 连排级战斗；1 个营级战斗剧本 + 1 个连排级新手教程；实体量级 300–800；单 tick 墙钟 ≤ 5 ms（4–8 线程）；内存 < 512 MB；启动数据校验 ≤ 5 s。
- **Rationale**: 营级是 v1 目标规模，5×5 km 与 300–800 实体使单 tick 计算量可控，同时支撑完整指挥链与 13 种任务类型；预算以数据配置校准而非硬编码。
- **Alternatives considered**: 两旅交战（后置，实体 2000+，超出 v1 性能与规模目标）；仅连排级（覆盖不足，用户决定营级为主）。
